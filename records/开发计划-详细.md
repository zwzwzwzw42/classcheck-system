# 课堂学情监控管理系统 — 详细开发计划

> 与 `开发计划.md`（总览）配套的详细执行版。按模块细化到：后端接口清单、核心类、业务逻辑要点、前端页面、验证方式、git 提交点。
> 开发节奏：每完成一个模块 → 编译+启动+接口/页面验证 → git 提交 → 更新本文件状态。

---

## 0. 总体路线图

```
环境与设计（已完成）→ 认证 → 反馈 → 统计 → 历史/导出 → 讨论 → 用户管理
→ 拓展模块 → 前端整合美化 → 联调+截图 → 文档+打包
```

依赖关系：
1. 认证模块最先（所有功能的前置，提供登录态与角色）
2. 反馈模块（数据源）
3. 统计模块（依赖反馈数据 + 课程归属；课程归属在拓展模块后才完整，故统计模块先做"默认课堂"口径，拓展模块完成后升级为按课程统计）
4. 历史查询/导出（依赖统计快照表）
5. 讨论区、用户管理（相互独立，可并行）
6. 拓展模块（最后接入，联动反馈与统计的课程维度）
7. 整合美化、联调截图、文档打包

## 2. 模块一：认证模块（任务4）

### 2.1 后端
| 接口 | 说明 |
|---|---|
| POST /api/auth/login | 密码登录：username+password，校验账号状态 |
| POST /api/auth/sms/send | 模拟发送短信验证码：生成6位码存内存(5分钟有效)，前端展示"验证码已发送" |
| POST /api/auth/sms/login | 短信登录：phone+code |
| POST /api/auth/third/login | 第三方模拟登录：platform(wechat/qq)+openid(演示用手机号代替) |
| POST /api/auth/logout | 登出，删除token |
| GET /api/auth/me | 返回当前登录用户信息（含角色） |

- 核心类：AuthController / AuthService / SysUserMapper / LoginInterceptor / UserContext / TokenStore
- Token 方案：登录成功生成 UUID token，存内存 `ConcurrentHashMap<token, 用户会话>`，响应头/体返回；前端存 localStorage，请求头带 `Authorization: Bearer <token>`
- 权限模型：URL 前缀 + 角色判断
  - `/api/student/**` → 学生
  - `/api/teacher/**` → 教师
  - `/api/admin/**` → 管理员
  - 其他业务接口 `/api/feedback`、`/api/discuss/**`、`/api/statistics` 等 → 登录即可 + 内部按角色校验
- 拦截器放行：`/api/auth/**`、`/api/health`、静态资源、login.html；未登录访问业务接口返回 code=401
- 密码存储：MD5 + 固定盐（课程作业场景，不引入 Spring Security 全家桶）
- 用户状态：status=0 禁用账号禁止登录

### 2.2 前端
- login.html 三个 tab：
  - 密码登录：用户名+密码
  - 短信登录：手机号 + 获取验证码按钮 + 验证码输入
  - 第三方：两个图标按钮（微信/QQ）→ 模拟授权弹窗（说明"模拟第三方授权"→ 选择演示账号 → 确认授权登录）
- 登录成功按角色跳转：学生→/student/home.html，教师→/teacher/home.html，管理员→/admin/home.html
- common.js 统一封装 fetch（自动带 token、401 跳登录页）

### 2.3 验证
1. 正确密码登录拿到 token；错误密码报错
2. 无 token 访问业务接口 → 401
3. 学生 token 访问 /api/teacher/** → 403
4. 短信登录：发送验证码→用验证码登录成功
5. 第三方模拟登录成功
6. 禁用账号登录被拒

### 2.4 提交点
`feat: 认证模块（密码/短信/第三方模拟登录+角色权限拦截）`

## 4. 模块三：定时统计与实时展示（任务5-后半）

### 4.1 统计口径（关键决策）
- 每个统计周期，**每个学生只算最后一次提交**（按 student+course 去重取最新 create_time）
- 指标：提交人数 total_count、平均分 avg_score（保留2位）、方差 variance（总体方差=Σ(x-μ)²/N）、各分数人数 score1~6_count
- 快照写入 statistics 表（stat_time, course_id, course_name, 指标列），历史可追溯
- 周期来源：sys_config.stats_period_minutes（5-10，管理员可配）
- 动态调度：实现 SchedulingConfigurer，每次调度前重读配置，修改周期无需重启

### 4.2 后端
| 接口 | 说明 |
|---|---|
| GET /api/statistics/latest?courseId= | 当前时段最新快照（教师端显著位置展示） |
| GET /api/statistics/history?courseId=&startTime=&endTime= | 历史快照列表（倒序） |
| GET /api/statistics/export?courseId=&startTime=&endTime= | 导出 Excel |
| GET /api/admin/config/stats-period | 查询当前周期 |
| PUT /api/admin/config/stats-period | 修改周期（校验 5≤minute≤10） |

- 统计聚合 SQL：对每个 course_id，`GROUP BY student_id` 取最新反馈 → 内存/一条 SQL 完成分布与均值方差
- StatsTask：`@Scheduled` 由 SchedulingConfigurer 动态触发 → StatsService.computeAndSave()

### 4.3 前端（teacher/home.html 实时统计页签）
- 顶部"当前时段"高亮卡片：提交人数 / 平均分 / 方差（大数字）
- 表情分布行：6 个表情各显示人数+百分比
- ECharts 柱状图（各分数人数）+ 饼图（占比）
- 课程筛选下拉（拓展模块提供）；刷新按钮（轮询30秒或手动）

### 4.4 验证
- 造数据：不同学生多次提交 → 核对人数（去重）、平均分、方差手算一致
- 管理员把周期改为 10 → 日志确认调度周期变化
- 图表渲染正确

- 验证：构造不同时间的快照 → 查询命中正确；导出文件用 Excel/WPS 打开字段齐全、中文不乱码

## 12. 关键设计决策汇总

| 主题 | 决策 | 理由 |
|---|---|---|
| 统计口径 | 每学生取最新反馈去重 | 与手册示例一致，避免重复提交虚增人数 |
| 方差 | 总体方差 Σ(x-μ)²/N | 指标明确、易手算核验 |
| 定时调度 | SchedulingConfigurer 动态读周期 | 改配置不重启，满足 5-10 分钟可配 |
| 密码 | MD5+固定盐 | 课程作业无需引入安全框架 |
| 会话 | 内存 token Map | 轻量，200并发场景足够，演示重启可接受 |
| 短信 | 模拟发送，验证码内存存 5 分钟 | 无真实短信服务，演示流程完整 |
| 第三方 | 模拟授权页选择演示账号 | 无真实微信/QQ 开发者资质 |
| 图片 | 本地 uploads/ 目录 + 静态映射 | 简单可靠 |
| 图表 | ECharts 本地文件 | 离线可运行、截图稳定 |
| 分页 | offset/limit 简单分页 | 数据量小，够用即可 |
