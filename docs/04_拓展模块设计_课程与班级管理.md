# 拓展模块设计：课程与班级管理

> 本模块为本人（学生）自主提出的新增业务模块，需求、功能与数据结构由本人设计，AI 仅作为实现辅助。

## 1. 需求背景

原系统中，学情反馈、定时统计都针对"全班"整体进行，缺少"按课程组织学情"的维度：
- 一位教师通常讲授多门课程，多个班级；不同课程、不同班级的学情应当分开统计与追溯；
- 学生提交反馈时不知道自己反馈的是哪门课，教师端看到的统计也无法区分课程；
- 教师无法便捷地维护自己名下的课程与班级学生名单，班级信息零散。

因此，本人设计「课程与班级管理」模块，作为学情监控的组织基础：教师创建/维护课程，为课程建立班级并维护班级学生名单；学生加入班级后，其反馈按课程归属，学情统计可按课程、班级维度独立查看，使整个系统的学情数据有了清晰的组织结构。

## 2. 功能设计

### 2.1 教师端
1. 课程管理：新增课程（课程名、简介）、编辑课程、删除课程、查看自己名下课程列表；
2. 班级管理：为课程创建班级、重命名班级、删除班级、查看班级学生名单；
3. 学生名单维护：从全校学生中选择学生加入班级，或从班级中移除学生。

### 2.2 学生端
1. 查看自己已加入的课程与班级列表；
2. 提交学情反馈时选择所属课程，反馈记录归属到该课程。

### 2.3 与主系统联动
- 学情定时统计按课程分别计算（每个课程一条统计快照）；
- 教师端实时统计与历史查询支持按课程筛选；
- 学生提交反馈时默认带出自己所在课程。

## 3. 数据结构（新增 3 张表）

见《03_数据库设计.md》：
- `course` 课程表：id、课程名、任课教师ID、简介、创建时间；
- `class_info` 班级表：id、班级名、所属教师ID、关联课程ID、创建时间；
- `class_student` 班级学生关联表：id、班级ID、学生ID、加入时间，唯一约束(班级,学生)防止重复加入。

## 4. 接口设计

| 方法 | 路径 | 角色 | 说明 |
|---|---|---|---|
| GET | /api/teacher/courses | 教师 | 查询自己名下课程列表 |
| POST | /api/teacher/courses | 教师 | 新增课程 |
| PUT | /api/teacher/courses/{id} | 教师 | 编辑课程 |
| DELETE | /api/teacher/courses/{id} | 教师 | 删除课程（级联删除其班级与班级学生关联） |
| GET | /api/teacher/courses/{id}/classes | 教师 | 查询课程下班级列表 |
| POST | /api/teacher/classes | 教师 | 新建班级 |
| DELETE | /api/teacher/classes/{id} | 教师 | 删除班级 |
| GET | /api/teacher/classes/{id}/students | 教师 | 查询班级学生名单 |
| GET | /api/teacher/students/all | 教师 | 查询全校学生（用于选择加入班级） |
| POST | /api/teacher/classes/{id}/students | 教师 | 添加学生到班级 |
| DELETE | /api/teacher/classes/{id}/students/{studentId} | 教师 | 从班级移除学生 |
| GET | /api/student/courses | 学生 | 查询自己已加入的课程与班级 |

## 5. 实现思路

- 后端：新增 CourseController、ClassController，Service 层做归属校验（教师只能操作自己的课程/班级），删除课程时事务性级联清理班级与学生关联；
- 前端：教师端新增"课程班级"页签，页面包含课程列表（增删改表单）、班级管理（选择课程→查看班级→维护学生名单，学生名单通过多选框从全校学生中添加）；
- 数据联动：反馈提交接口接收 courseId；统计任务按 courseId 分组统计；教师实时统计/历史查询页面增加课程下拉筛选（数据来源于本模块）。
